# Code of conduct

## The short version

Be decent. Discuss the code, not the person who wrote it.

## Expected behaviour

- Assume competence and good faith; a question is a question, not an attack.
- Review the change, not the author. "This breaks on an empty bbox" is a
  review; "you never think about edge cases" is not.
- Accept that a maintainer may decline a change. A fork is a legitimate answer
  to a disagreement — this project is meant to be forkable.
- Respect that contributors write in different languages and time zones, and
  that most of them are doing this in spare time.

## Unacceptable behaviour

- Personal attacks, insults, and harassment in any form.
- Discrimination or demeaning remarks about people, including on the basis of
  origin, gender, orientation, religion, age, or disability.
- Publishing someone's private information without their explicit permission.
- Deliberate derailing: repeated off-topic argument, spam, or pressure on a
  contributor after a decision has been made.

This applies everywhere the project happens: issues, pull requests, commit
messages, code and documentation.

## Enforcement

Report a problem privately to the maintainers through GitHub — a private
security advisory in this repository works for this too and is not visible to
other users.

Maintainers may edit or delete comments, close issues and pull requests, and
block accounts. The response depends on how serious and how repeated the
behaviour is; a one-off rude comment is not treated like sustained harassment.
Reports are handled confidentially, and the reporter is not required to argue
their case in public.
