# Контракт: RecentEventsCache

Стык внутри бэкенда. Одна половина трека наполняет кэш из очереди, вторая
читает его и отдаёт наружу. Меняется с согласия обеих сторон.

## Интерфейс

```java
public interface RecentEventsCache {
    /** Кладёт событие. Вызывает только поллер. */
    void put(EnrichedEvent event);

    /** Снимок на момент вызова: ключ — h3_r9, значение — события ячейки. */
    Map<String, List<EnrichedEvent>> snapshot();
}
```

Чтение — снимком, а не по ключам: карта сворачивает ключи кэша вверх до нужной
резолюции, поэтому нужен обход всех ячеек. Разворот запроса вниз до r9
неприменим — от r3 до r9 получается около 117 тысяч дочерних ячеек на одну.

## Кто за что отвечает

| Гарантирует запись | Может рассчитывать чтение |
|---|---|
| ключ — H3-индекс уровня 9, как пришёл из очереди | не проверяет формат ключа |
| в кэше нет событий старше 30 минут | не фильтрует по времени |
| нет дублей по `event_id` | не дедуплицирует |
| коллекции иммутабельны, обход безопасен | не копирует защитно |
| ячейка без событий исчезает из снимка | не проверяет пустые списки |
| пустой кэш — пустая мапа | не проверяет на `null` |
| события в ячейке идут от новых к старым | может обрезать длинные списки |

География, bbox и резолюции — не зона записи. Структура хранения, вытеснение
и выбор библиотеки — не зона чтения.

## Открытые вопросы

- **Лимит событий в ячейке.** В [rest-api](rest-api.md) ограничения нет.
  Активная ячейка за полчаса наберёт сотни правок, и весь список уедет в JSON.
  Решить, где режем — при записи или при отдаче.
- **Потолок кэша.** Сколько событий даёт получасовое окно на четырёх вики —
  неизвестно. Померить на моке до подключения к кластеру и, если много,
  задать правило вытеснения.

## Известное ограничение

**У события нет времени правки.** `EnrichedEvent` содержит `event_id`, `title`,
`url` и `h3_r9`; поля `event_ts` в [q_enriched](yt-schemas.md) тоже нет.

Значит окно в 30 минут считается по времени получения, а не по времени правки.
Пока поллер идёт ровно, разницы нет. После переподключения или отставания
в кэш разом попадут события часовой давности с меткой «только что».

Чинится одним полем `event_ts` в очереди — это же даёт корректную сортировку.
Поднять с треком P до того, как джоба обогащения зафиксируется.
