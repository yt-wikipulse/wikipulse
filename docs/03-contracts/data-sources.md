# Контракт: внешние источники данных

Граница между проектом и чужими сервисами. Здесь описано, что WikiPulse
берёт снаружи, какие поля из этого реально читает и на каких условиях всё
это разрешено использовать.

Источников четыре: поток правок Wikimedia, дамп Wikidata, MediaWiki Action API
и JavaScript API Яндекс Карт. Первые два питают пайплайн, третий вызывается
из браузера напрямую, четвёртый рисует карту.

## Поток правок Wikimedia (EventStreams)

```
https://stream.wikimedia.org/v2/stream/recentchange
```

Server-Sent Events, публичный, без ключа и регистрации. Читает
[`bigdata/src/bigdata/jobs/ingestor.py`](../../bigdata/src/bigdata/jobs/ingestor.py),
пишет в `q_raw` пачками по 100 строк.

### Поля события, которые читает ингестор

| Поле события | Куда едет | Зачем |
|---|---|---|
| `wiki` | `wiki` | языковой раздел, ключ джойна со справочником |
| `title` | `title` | заголовок статьи; подчёркивания заменяются пробелами |
| `title_url` | `url` | готовая ссылка на статью |
| `timestamp` | `event_ts` | время правки, unix-секунды |
| `revision.new` | часть `event_id` | номер новой ревизии |
| `notify_url` | `diff_url` | ссылка на диф правки |
| `length.new`, `length.old` | `length_update` | разность даёт прирост в байтах |
| `bot` | — | фильтр: правки ботов отбрасываются |
| `namespace` | — | фильтр: только `0`, то есть статьи |
| `type` | — | фильтр: только `edit` и `new` |

Остальное поток тоже присылает — `meta`, `user`, `comment`, `minor`,
`server_name` и прочее, — но ингестор это не читает и в `q_raw` не кладёт.
Схема очереди — в [yt-schemas.md](yt-schemas.md).

`event_id` собирается как `{wiki}|{revision.new}` — например
`enwiki|1372099064`. Номер ревизии уникален внутри своего раздела, но не
между разделами, поэтому раздел входит в ключ. Этот идентификатор служит
ключом дедупликации на всём пути: от очереди до кэша живой карты и до
дедупа в джобе витрин.

### Как ингестор ведёт себя с потоком

- Одно соединение, `stream=True`, таймаут 90 секунд.
- Обрыв (`ConnectionError`, `Timeout`, `ChunkedEncodingError`) — пауза
  5 секунд и переподключение. Ошибка YTsaurus — пауза 10 секунд.
- При переподключении уходит заголовок `Last-Event-ID` с идентификатором
  последнего разобранного события: сервер досылает пропущенное, а не
  начинает с текущего момента.
- Заголовок `User-Agent` обязателен и собирается в
  [`runtime.py`](../../bigdata/src/bigdata/runtime.py) из `WIKIPULSE_CONTACT`.

## Дамп Wikidata

```
https://dumps.wikimedia.org/wikidatawiki/entities/latest-all.json.gz
```

Полный дамп сущностей, по одному JSON-объекту на строку. Читает
[`bigdata/src/bigdata/scripts/load_dict_coords_full.py`](../../bigdata/src/bigdata/scripts/load_dict_coords_full.py),
пишет справочник `dict/coords`.

### Что берётся из сущности

| Путь в JSON | Куда едет |
|---|---|
| `claims.P625[0].mainsnak.datavalue.value.latitude` | `lat` |
| `claims.P625[0].mainsnak.datavalue.value.longitude` | `lon` |
| `sitelinks.<wiki>.title` | `title`, по строке на каждый языковой раздел |

`P625` — свойство «координаты объекта». Сущности без него пропускаются
дешёвой проверкой подстроки `"P625"` в сырой строке, до разбора JSON:
координаты есть у единиц процентов сущностей, и разбирать остальные незачем.

Из сайтлинков берутся только языковые разделы Википедии — имя оканчивается
на `wiki`, и это не `wikidatawiki`, `commonswiki`, `metawiki`, `abstractwiki`.
Так фильтр справочника совпадает с фильтром ингестора, иначе в справочнике
лежали бы ключи, которые никогда не совпадут с событием.

### Как загрузчик ведёт себя с дампом

- Одно потоковое соединение, gzip распаковывается на лету — файл целиком
  на диск не кладётся.
- Проход по полному дампу длинный, поэтому есть `--max-rows` для пробного
  прогона.
- Результат сначала пишется во временную таблицу, потом сортируется
  на кластере в `dict/coords`, временная удаляется.
- Тот же `User-Agent` из `WIKIPULSE_CONTACT`.

Обновлять справочник имеет смысл не чаще, чем выходит новый дамп, — раз
в неделю.

## MediaWiki Action API

```
https://<раздел>.wikipedia.org/w/api.php
```

Единственный источник, к которому ходит не пайплайн, а браузер
пользователя — [`frontend/src/api/wikiDiff.ts`](../../frontend/src/api/wikiDiff.ts).
Бэкенд диф не проксирует и не хранит.

| Запрос | Зачем |
|---|---|
| `action=compare&fromrev=&torev=&prop=diff` | HTML-таблица дифа двух ревизий |
| `action=query&prop=revisions&rvprop=ids` | номера ревизий, если их не удалось достать из `diff_url` |

Оба запроса идут с `format=json`, `formatversion=2` и `origin=*` — последнее
включает анонимный CORS, без него браузер не отдал бы ответ странице.

Домен берётся из `url` события, то есть у каждой правки спрашивается её
собственный языковой раздел.

## JavaScript API Яндекс Карт

Карту рисует JS API 3.0. Скрипт грузится из кода
([`loadYmaps.ts`](../../frontend/src/components/LiveMap/loadYmaps.ts)),
ключ приходит с бэкенда по `GET /api/v1/config` — см.
[rest-api.md](rest-api.md). Ключ публичный: он уходит в браузер и виден
в отладчике, а от чужого использования его защищает ограничение по
HTTP Referer в Кабинете разработчика.

## Юридические обязательства

Это не юридическая консультация, а список того, что уже учтено в коде
и что обязан сделать форкер.

### Тексты Википедии — CC BY-SA

Статьи Википедии распространяются по лицензии
[Creative Commons Attribution-ShareAlike](https://creativecommons.org/licenses/by-sa/4.0/)
(актуальная версия — 4.0; часть старых материалов доступна ещё и по GFDL).
Лицензия требует при воспроизведении текста указывать авторство, сохранять
ссылку на лицензию и распространять производное на тех же условиях.

Где это касается WikiPulse: в поповере дифа показываются фрагменты текста
статьи. Заголовки, ссылки и счётчики правок — фактические сведения, они
лицензией не покрыты, а вот сам текст дифа — да.

Что сделано: каждая правка ведёт ссылкой на статью и на диф в самой
Википедии, показываются только первые несколько строк дифа.

Что не сделано и должно быть сделано перед публичным запуском: в интерфейсе
нет явной строки с указанием источника и лицензии рядом с текстом дифа.
Форкеру, который поднимает сервис публично, эту строку нужно добавить.

### Данные Wikidata — CC0

Содержимое Wikidata выпущено под
[CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/): координаты
можно использовать без указания авторства. Ссылка на источник — вежливость,
а не обязанность.

### User-Agent policy Wikimedia

[Политика Wikimedia](https://meta.wikimedia.org/wiki/User-Agent_policy)
требует от автоматических клиентов информативный `User-Agent` с рабочим
способом связи. Запросы с пустым или обобщённым заголовком могут получать
`403`, а при нагрузке — бан по IP.

В проекте заголовок собирается один раз в `runtime.USER_AGENT` и уходит
и в SSE-поток, и в загрузку дампа:

```
WikiPulse/0.1 (<значение WIKIPULSE_CONTACT>)
```

`WIKIPULSE_CONTACT` — переменная окружения, по умолчанию канонический URL
проекта. **Форкер обязан подставить свой контакт**: URL своего репозитория
или адрес почты. Оставить чужой — значит слать претензии по чужому адресу.

Запросы фронтенда к Action API политика не затрагивает: их делает браузер
пользователя со своим собственным `User-Agent`.

### Этикет работы с дампами

`dumps.wikimedia.org` — общий ресурс фонда, оплаченный пожертвованиями.
Правила простые и в проекте соблюдаются:

- одно соединение на загрузку, без параллельной качки кусками;
- дамп берётся не чаще, чем он обновляется, — раз в неделю;
- при ошибке не долбить в цикле, а отступать;
- если нужен регулярный полный проход — использовать зеркала из списка
  на сайте дампов.

Для отладки существует `--max-rows`: пробовать изменения в парсере
на полном дампе не нужно.

### Условия использования API Яндекс Карт

Ключ выдаётся в Кабинете разработчика, использование регулируется
[условиями использования API Яндекс Карт](https://yandex.ru/legal/maps_api/).
Практические следствия, уже учтённые в коде:

- **Копирайты, логотип и кнопка перехода в Яндекс Карты должны быть видны
  и не перекрыты** другими элементами. Из-за этого в `LiveMap.tsx` кнопка
  переставляется на узких экранах, а не прячется, — подробности в
  [frontend-implementation-notes.md](../02-architecture/frontend-implementation-notes.md).
- **Бесплатный тариф рассчитан на общедоступный сервис** и ограничен по
  числу загрузок карты в сутки. Исчерпание квоты выглядит как «скрипт
  загрузился, а карта не рисуется» — этот симптом разобран в
  [troubleshooting.md](../05-runbooks/troubleshooting.md).
- **Ключ ограничивается по HTTP Referer** в Кабинете разработчика. Это
  единственная защита публичного ключа, и настроить её должен владелец
  стенда.

Свой ключ форкер получает сам: чужой ключ в репозитории — это и нарушение
условий, и чужой счёт.
