# Контракт: REST API

Два экрана: живая карта и дашборд.

## Общие правила

- Базовый путь: `/api/v1`.
- Формат: JSON, имена полей — `snake_case`.
- Карта обновляется поллингом раз в 2–3 секунды, дашборд — по запросу.
- Ошибки — Problem Details:

```json
{
  "type": "about:blank",
  "title": "Bad Request",
  "status": 400,
  "detail": "zoom must be between 0 and 30"
}
```

## `GET /api/v1/hexagons/active`

Активность в видимой части карты. Фронт присылает прямоугольник экрана
и текущий зум, бэкенд сам выбирает резолюцию H3.


|Параметр|Тип|Описание|
|:---|:---|:---|
|`min_lng`|number|западная граница экрана|
|`min_lat`|number|южная граница|
|`max_lng`|number|восточная граница|
|`max_lat`|number|северная граница|
|`zoom`|number|зум карты, бэкенд переводит его в резолюцию H3|

Пример:

```
GET /api/v1/hexagons/active?min_lng=37.31&min_lat=55.57&max_lng=37.85&max_lat=55.91&zoom=10
```

Ответ:

```json
{
  "hexagons": [
    {
      "h3_index": "8611aa7afffffff",
      "events_count": 1,
      "events": [
        {
          "id": "123456789",
          "title": "Москва",
          "url": "https://ru.wikipedia.org/wiki/Москва"
        }
      ]
    }
  ]
}
```

Query-параметры в ответе не дублируются: резолюцию фронт знает по своему зуму.

### Что делает бэкенд

1. Переводит `zoom` в целевую резолюцию H3.
2. Строит из четырёх координат полигон и получает список ячеек этой
   резолюции — `polygonToCells`.
3. Для каждой ячейки получает дочерние уровня 9 — `cellToChildren`,
   потому что кэш хранит события с ключом `h3_r9`.
4. Читает по этим ключам `RecentEventsCache` и группирует события обратно
   по ячейке целевой резолюции.

Вся арифметика H3 живёт в одном классе `H3GeoService`.

### Окно

События хранятся в кэше **30 минут**. Ячейки без событий за это окно
в ответ не попадают: пустой список `hexagons` — нормальный ответ, а не ошибка.

## `GET /api/v1/dashboard`

Историческая аналитика поверх витрин. Витрины пересчитываются раз в час,
поэтому поллинг не нужен — запрос делается при открытии экрана и при смене
периода.

| Параметр | Тип | Обяз. | Описание |
|---|---|---|---|
| `period` | `24h` \| `7d` \| `30d` | да | окно агрегации |
| `limit` | number, 1–100 | нет | длина топов, по умолчанию 10 |

Пример:

```
GET /api/v1/dashboard?period=24h
```

Ответ:

```json
{
  "period": "24h",
  "generated_at": 1755216000,
  "bucket_seconds": 3600,
  "total_edits": 126214,
  "trends": [
    { "bucket_ts": 1755216000, "edits_count": 4210 }
  ],
  "top_articles": [
    {
      "title": "Federal Reserve",
      "url": "https://en.wikipedia.org/wiki/Federal_Reserve",
      "edits_count": 18420
    }
  ],
  "top_geo": [
    {
      "h3_parent": "8428d1ffffffff",
      "top_title": "Teotihuacán",
      "top_url": "https://en.wikipedia.org/wiki/Teotihuacan",
      "edits_count": 9840,
      "articles_count": 312
    }
  ]
}
```

### Поля

| Поле | Что означает |
|---|---|
| `period` | эхо запроса, чтобы клиент не сверялся со своим состоянием |
| `generated_at` | когда витрины были пересчитаны, unix-секунды |
| `bucket_seconds` | шаг между точками `trends`, зависит от периода |
| `total_edits` | сумма `edits_count` по всем точкам `trends` |
| `trends[].bucket_ts` | начало интервала, unix-секунды |
| `top_articles[]` | самые правимые статьи периода |
| `top_geo[].h3_parent` | H3-ячейка; резолюция закодирована в самом индексе |
| `top_geo[].top_title` | самая правимая статья внутри ячейки |
| `top_geo[].articles_count` | сколько разных статей затронуто в ячейке |

Время везде в unix-секундах — как `event_ts` в очереди. ISO-строк в дашборде
нет намеренно: точки графика удобнее считать числами.

### Периоды и витрины

Наружу отдаются читаемые `24h`, `7d`, `30d`. Витрины хранят период строкой
в часах, поэтому бэкенд переводит значение перед запросом:

| Запрос | В витрине |
|---|---|
| `24h` | `24h` |
| `7d` | `168h` |
| `30d` | `720h` |

Перевод живёт на бэкенде: репозиторий и таблицы на кластере не меняются.
Если строк за нужный период в витрине нет, ответ придёт пустым — см. ниже.

### Шаг графика

`bucket_seconds` не выдумывается клиентом, его задаёт бэкенд:

| `period` | `bucket_seconds` | Точек в графике |
|---|---|---|
| `24h` | 3600 (час) | 24 |
| `7d` | 3600 (час) | 168 |
| `30d` | 86400 (сутки) | 30 |

Причина в читаемости: месяц почасовыми точками — это 720 значений, график
превращается в шум.

Часового окна нет намеренно: витрина хранит часовые строки, и за час
получилась бы одна точка. Более мелкий шаг потребовал бы отдельного
пересчёта в пайплайне, а для MVP это не окупается.

### Пустые данные

Витрина может быть ещё не посчитана — тогда `trends`, `top_articles`
и `top_geo` приходят пустыми массивами, а `total_edits` равен нулю.
Это нормальный ответ, не ошибка. Пустой экран дашборда объясняет пользователю,
что данных пока нет.

### Ошибки

Неизвестный `period` — `400`:

```json
{
  "type": "about:blank",
  "title": "Bad Request",
  "status": 400,
  "detail": "period must be one of 24h, 7d, 30d"
}
```

Витрины недоступны — `503`. Устаревшие данные вместо ошибки не отдаются:
показывать вчерашние цифры без пометки значит врать.

### Согласованность

Три блока читаются из трёх разных витрин отдельными запросами. Между ними
батч-джоба может пересчитать часть таблиц, поэтому блоки способны относиться
к соседним пересчётам. Для почасовых агрегатов это незаметно, но `total_edits`
считается **из тех же точек `trends`**, что уехали в ответ, — чтобы сумма
на экране всегда сходилась с графиком.

## `GET /api/v1/config`

Настройки, которые фронтенд получает в рантайме: ключ JavaScript API
Яндекс Карт.

Параметров нет.

Ответ:

```json
{
  "ymaps_api_key": "<ключ из Кабинета разработчика>"
}
```

Ключ приходит из окружения бэкенда (`app.ymaps.api-key`), а не из сборки
фронтенда. Смена ключа поэтому не требует пересборки образа `web` — достаточно
поменять значение в `deploy/.env` и поднять контейнеры заново. Это же делает
проект пригодным для форка: тот, кто клонирует репозиторий, подставляет свой
ключ, не трогая код.

Ключ публичный — он уходит в браузер и виден в отладчике. От чужого
использования его защищает ограничение по HTTP Referer в кабинете Яндекса,
где для ключа прописан домен сайта.

### Ключ не задан

Отдаётся `200` с пустой строкой:

```json
{
  "ymaps_api_key": ""
}
```

Отсутствие ключа не ошибка запроса, поэтому не `5xx`. Карта в этом случае
не инициализируется и показывает ошибку загрузки, остальная страница работает.

## Отложено до v2

**Поля правки.** Отдаются только `id`, `title` и `url`. Язык, флаг бота,
размер правки, страна и тип места в ответе не участвуют.

## Что проверяется на первом живом запуске

**Какие окна реально считает джоба витрин.** Перевод `7d` → `168h` и
`30d` → `720h` сделан по формату колонки `period` из
[yt-schemas](yt-schemas.md). Если джоба считает только сутки, ответы за неделю
и месяц придут пустыми — тогда либо джоба добавляет окна, либо периоды
убираются из этого контракта.
