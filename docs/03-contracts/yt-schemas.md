# Контракт: схемы таблиц и очередей YT

Граница между пайплайном и бэкендом. Меняется с аппрувом обеих сторон:
P2 пишет данные, B их читает.

MVP v1 — минимальный набор полей, которого хватает живой карте. Реальные
таблицы на кластере шире: контракт описывает **обязательный минимум**,
лишние колонки не мешают.

Имена полей — `snake_case`. Пути на кластере — в `bigdata/src/bigdata/config`,
в коде не хардкодятся.

## Объекты

| Путь | Тип | Пишет | Читает |
|---|---|---|---|
| `q_raw` | queue | SSE-сборщик | SPYT-джоба обогащения |
| `dict/coords` | static | загрузчик справочника | SPYT-джоба обогащения |
| `q_enriched` | queue | SPYT-джоба обогащения | бэкенд, архиватор |
| `history/t_history` | static | архиватор | SPYT-джоба витрин |
| `marts/trends` | dynamic | SPYT-джоба витрин | бэкенд |
| `marts/top_articles` | dynamic | SPYT-джоба витрин | бэкенд |
| `marts/top_geo` | dynamic | SPYT-джоба витрин | бэкенд |

## q_raw

Сырые правки из потока Википедии. Схема нестрогая (`strict = false`) —
лишние поля источника можно класть без правки контракта.

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `$timestamp` | uint64 | да | служебное поле очереди |
| `event_id` | string | да | идентификатор правки |
| `wiki` | string | да | `enwiki`, `ruwiki` — ключ джойна |
| `title` | string | да | заголовок статьи — ключ джойна |
| `url` | string | да | ссылка на статью |

Фильтр на входе: только правки статей, `type = edit`.

## dict/coords

Справочник координат из дампа WikiData, обновляется раз в неделю.
Отсортирован по ключу джойна.

| Поле | Тип | Ключ | Описание |
|---|---|---|---|
| `wiki` | string | да | языковой раздел |
| `title` | string | да | заголовок статьи |
| `lat` | double | | широта |
| `lon` | double | | долгота |

В справочник попадают только статьи, у которых в WikiData есть координаты.

## q_enriched

Главный объект контракта: из него бэкенд строит карту.

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `event_id` | string | да | идентификатор правки, он же `id` в ответе API |
| `title` | string | да | заголовок статьи |
| `url` | string | да | готовая ссылка, бэкенд её не собирает |
| `h3_r9` | string | да | ячейка H3 уровня 9 |

**Только уровень 9.** Ячейки крупнее бэкенд получает арифметикой H3 из этой,
класть в очередь `h3_r3` и `h3_r6` не нужно.

**Правки без координат в очередь не попадают.** Джойн со справочником —
inner, статья без геометки отбрасывается на стороне пайплайна.

### Чтение очереди

Консьюмер не используется. Бэкенд держит курсор по `$row_index` в памяти
поллера и читает строки с индексом больше курсора.

При старте курсор ставится на конец очереди: история бэкенду не нужна,
кэш всё равно хранит только последние 30 минут. Отсюда следует, что после
рестарта всё прочитанное до него не возвращается — и это осознанный выбор,
а не потеря данных.

Курсор двигается на `lastRowIndex` из ответа, а не на размер порции:
в очереди бывают пропуски после вычистки старых строк.

Падение между чтением и укладкой в кэш теряет порцию: курсор уже сдвинут,
повторно эти строки не придут. При окне в 30 минут потеря секунды незаметна.
Дедупликация по `event_id` в кэше на месте и защищает от повторов.

События живут в кэше 30 минут.

## Отложено до v2

Колонки правки, которых нет в потоке: язык, флаг бота, размер правки,
страна, тип места. Если дашборду понадобятся разрезы по ним — сначала
расширяется ингестор и `q_raw`, потом сюда возвращаются их схемы.

## history/t_history

Статическая таблица-архив: источник всех витрин дашборда. Архиватор раз в
час дописывает новые строки `q_enriched` (курсор — атрибут
`@archiver_last_row_index`). Схема зеркалит `q_enriched`.

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `event_id` | string | да | идентификатор правки, ключ дедупа в витринах |
| `title` | string | да | заголовок статьи |
| `url` | string | да | готовая ссылка |
| `h3_r9` | string | да | ячейка H3 уровня 9 |
| `event_ts` | uint64 | да | время правки, unix-секунды |

Дубли `event_id` возможны (падение архиватора между записью и курсором) —
джоба витрин дедуплицирует по `event_id` сама, читателю об этом знать
не обязательно.

## marts/trends

Количество правок по часам. Накопительная витрина: каждый пересчёт
перезаписывает бакеты попавшего в окно диапазона часов, старые часы
остаются как история.

| Поле | Тип | Ключ | Описание |
|---|---|---|---|
| `bucket_ts` | uint64 | да | unix-время начала часа |
| `edits_count` | int64 | | число правок за час |

## marts/top_articles

Топ правимых статей за окно. Снапшот последнего пересчёта: каждый запуск
перезаписывает те же ключи `period` + `rank`, stale-строк не бывает.

| Поле | Тип | Ключ | Описание |
|---|---|---|---|
| `period` | string | да | окно пересчёта, например `24h` |
| `rank` | int64 | да | место в топе, с 1 |
| `title` | string | | заголовок статьи |
| `url` | string | | ссылка на статью |
| `edits_count` | int64 | | правки статьи за окно |

При равных `edits_count` выше ставится статья выше по алфавиту — порядок
стабилен между пересчётами.

## marts/top_geo

Топ гео-мест за окно. Ячейки `h3_r9` сворачиваются до резолюции 4
(регион/крупный город, меняется параметром джобы). Снапшот последнего
пересчёта, как у `top_articles`.

| Поле | Тип | Ключ | Описание |
|---|---|---|---|
| `period` | string | да | окно пересчёта, например `24h` |
| `rank` | int64 | да | место в топе, с 1 |
| `h3_parent` | string | | ячейка H3 уровня 4 |
| `top_title` | string | | самая правимая статья ячейки |
| `top_url` | string | | её ссылка |
| `edits_count` | int64 | | правки всех статей ячейки за окно |
| `articles_count` | int64 | | уникальных статей ячейки за окно |

У витрин есть отладочные атрибуты: `@computed_at`, `@window_hours`,
у топов — `@top_n`, у `top_geo` — `@h3_res`.

Дальнейший путь данных: витрины читает бэкенд (`YtAggregatesRepository`)
и отдаёт фронту отдельным REST-эндпоинтом дашборда.

## Известное ограничение

Чтение идёт только из нулевого таблета: в запросе стоит `[$tablet_index] = 0`.
Пока таблет один, это ничего не меняет. Если их станет больше, часть событий
пропадёт из карты молча — поэтому при любом изменении партиционирования
`q_enriched` запрос надо править первым делом.

Имена объектов пишем в нижнем регистре, как в коде и на кластере:
`q_enriched`, `q_raw`, `dict/coords`. Верхний регистр остался от ранних схем
и в документах не используется.
