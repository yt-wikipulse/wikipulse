# Пайплайн на локальном кластере YTsaurus

Путь от чистого клона до работающего пайплайна на кластере, который поднят
на твоей машине. Кластера с хакатона больше нет, а пример, которому нужен
чужой кластер, не форкается по определению.

Если кластер не нужен и достаточно посмотреть продукт — профиль `mock`
из [local-setup.md](local-setup.md) показывает обе страницы на настоящих
данных без единого контейнера.

Переменные окружения одной таблицей — в [configuration.md](configuration.md).

## Что проверено, а что нет

Шаги 1–6 пройдены целиком 30 августа 2026 на Windows 11 и Docker 25.0.3,
образ `ghcr.io/ytsaurus/local:stable`. Проверялось так: `init-tables`
создал все объекты, `ingestor` за минуту положил 200 строк в `q_raw`,
бэкенд на профиле `yt` прочитал `q_enriched` и отдал событие в API.

**Не проверено: SPYT.** Обе джобы на кластере — `spyt_enrich` (обогащение
`q_raw` → `q_enriched`) и `spyt_marts` (витрины) — запускаются через
`spark-submit` с `--master ytsaurus://…`, и на локальном кластере этот путь
никто не проходил. Понадобится как минимум подобрать версию `ytsaurus-spyt`
под версию локального кластера и питон его узлов, а хватит ли одного узла
на Spark-операцию — открытый вопрос. Это отдельное исследование, а не шаг
инструкции. Практическое следствие: `q_enriched` сам собой не наполнится, и
витрины не посчитаются. Проверить бэкенд поверх кластера это не мешает —
см. шаг 6.

## 1. Поднять кластер

Нужен только Docker и около 7 ГБ на диске: скрипт тянет два образа,
`ghcr.io/ytsaurus/local` (≈5,2 ГБ) и `ghcr.io/ytsaurus/ui` (≈0,6 ГБ). Сам
скрипт живёт в репозитории YTsaurus и целиком помещается в один файл:

```bash
curl -O https://raw.githubusercontent.com/ytsaurus/ytsaurus/main/yt/docker/local/run_local_cluster.sh
bash run_local_cluster.sh --rpc-proxy-count 1
```

**`--rpc-proxy-count 1` обязателен.** По умолчанию скрипт поднимает ноль
RPC-прокси, а и бэкенд, и `spark-submit` ходят в YTsaurus именно по RPC.
HTTP-прокси (`bigdata`, `yt` CLI) работает и без этого флага.

Что получится:

| Порт | Что |
|---|---|
| 8000 | HTTP-прокси кластера |
| 8001 | веб-интерфейс |
| 8002 | RPC-прокси |

Проверка, что кластер жив и RPC-прокси видна снаружи контейнера:

```bash
curl -s http://localhost:8000/api/v4/get?path=//sys/@cluster_name
curl -s "http://localhost:8000/api/v4/discover_proxies?type=rpc"
```

Ответы — `{"value":"locasaurus"}` и `{"proxies":["localhost:8002"]}`. Второй
важнее: клиент сначала спрашивает у HTTP-прокси адреса RPC-прокси и потом
идёт по ним, поэтому в ответе должен стоять адрес, который резолвится
с твоей машины. За это отвечает `--docker-hostname` (по умолчанию
`localhost`).

Остановить: `bash run_local_cluster.sh --stop`.

**Данные живут, пока живёт контейнер.** Скрипт запускает его с `--rm`,
так что после `--stop` кластер поднимается пустым и шаги 3–5 нужно
повторять.

Аутентификация по умолчанию выключена: `YT_TOKEN` всё равно должен быть
задан (его требуют и `bigdata`, и бэкенд), но значение подойдёт любое.

## 2. Переменные окружения

```bash
export YT_PROXY=http://localhost:8000
export YT_TOKEN=dummy
export YT_BASE_PATH=//home/wikipulse
```

**Бэкенду нужен тот же адрес без схемы** — `YT_PROXY=localhost:8000`.
Java-клиент получает значение как есть, а `bigdata` дописывает `https://`,
если схемы нет, и на локальном кластере по HTTP это ломается. На обычном
кластере разницы не видно.

## 3. Установить пакет `bigdata`

```bash
cd bigdata
python -m venv .venv && . .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -e .
```

Вместе с пакетом ставится клиент YTsaurus, а с ним — CLI `yt` и команды
`init-tables`, `ingestor`, `archiver`, `upload-artifacts`, `scheduler`.

## 4. Создать таблицы

```bash
init-tables
yt list $YT_BASE_PATH
```

Проходит на минимальном кластере целиком: каталоги, обе очереди как
динамические таблицы, оба консьюмера с регистрацией `vital`,
`auto_trim_config` на очередях, справочник, история и три витрины.

Очереди и консьюмеры на минимальном кластере работают, настраивать под них
ничего не надо: `run_local_cluster.sh` поднимает один queue agent сам
(`--queue-agent-count`, по умолчанию 1). Сам агент нужен не для чтения и
записи — этим занимаются обычные `insert-rows`/`select-rows`, — а для
авто-трима и мониторинга очередей. Работает ли авто-трим на локальном
кластере, не проверялось; известное ограничение по триму `q_enriched`
описано в `bigdata/implementation-notes.md`.

## 5. Наполнить `q_raw`

```bash
ingestor
```

Читает SSE-поток `stream.wikimedia.org` и пишет отфильтрованные правки
пачками по 100 строк. За минуту в очередь приезжает пара сотен строк:
из потока отсеиваются боты, служебные пространства имён и не-статейные
вики, поэтому `in` в логе на порядок больше `out`.

```bash
yt select-rows "* from [$YT_BASE_PATH/q_raw] limit 5" --format '<encode_utf8=false>json'
```

Останавливается по Ctrl+C. Дальше по схеме пайплайна идёт `spyt_enrich`,
которого на локальном кластере нет, — см. предупреждение в начале.

## 6. Бэкенд поверх локального кластера

```bash
cd backend
SPRING_PROFILES_ACTIVE=yt YT_PROXY=localhost:8000 YT_TOKEN=dummy \
  YT_BASE_PATH=//home/wikipulse ./mvnw spring-boot:run
```

Профиль `yt` — тот же, что и в проде: `YtQueuePoller` читает `q_enriched`,
`YtDashboardService` — витрины. Пустые таблицы не ошибка: дашборд отдаёт
корректный ответ с нулями, карта — пустой список.

Смоук-тест без SPYT — положить строку в `q_enriched` руками. Поллер на
старте перематывает очередь в конец (`skipToLatest`), поэтому строку надо
вставлять уже после запуска бэкенда:

```python
import time, h3
import yt.wrapper as yt
from bigdata import paths

yt.insert_rows(paths.Q_ENRICHED, [{
    "event_id": "ruwiki|1",
    "title": "Москва",
    "url": "https://ru.wikipedia.org/wiki/Москва",
    "h3_r9": h3.latlng_to_cell(55.75, 37.62, 9),
    "event_ts": int(time.time()),
    "length_update": 7,
    "diff_url": "https://ru.wikipedia.org/w/index.php?diff=1",
}])
```

```bash
curl -s "http://localhost:8080/api/v1/hexagons/active?min_lng=30&min_lat=50&max_lng=45&max_lat=60&zoom=10"
```

Событие появляется в ответе в течение секунды (`app.poller.interval-ms: 500`)
и живёт в кэше 30 минут.

## 7. Фронтенд

Ничем не отличается от обычного локального запуска — `pnpm dev` и
`http://localhost:5173/map`, см. [local-setup.md](local-setup.md).

## Чего на локальном кластере нет

- **Агрегатных функций в `select-rows`.** `count`, `max` и прочие ищутся
  как UDF в `//tmp/udfs`, а в локальном образе этого узла нет — запрос
  падает с `Function "count" is not known`. Пайплайна это не касается
  (агрегаты считает Spark), но диагностические запросы вида
  `max(event_ts) … group by 1` придётся заменить на `limit`.
- **SPYT.** См. предупреждение в начале.
- **Полного справочника координат.** `load-dict-coords-full` разбирает дамп
  Wikidata целиком; для проверки есть `--max-rows`, но без обогащения
  (тот же SPYT) справочник всё равно некуда применить.
- **Отказоустойчивости.** Один узел, всё в одном контейнере. Документация
  YTsaurus прямо говорит не использовать эту конфигурацию для прода и для
  замеров производительности.
