# Локальный запуск

Как поднять WikiPulse на своей машине с нуля. Шаги проверены на чистом клоне;
если шаг не работает — это баг документа, а не твоей машины.

Грабли, которые встречались в процессе, вынесены в
[troubleshooting.md](troubleshooting.md).

## Что нужно поставить

| Инструмент | Версия | Зачем |
|---|---|---|
| JDK | 17 | `java.version` в `backend/pom.xml`; проверено на 17.0.20 |
| Node.js | `^20.19` или `>=22.12` | требование Vite 8; проверено на 24.18 |
| pnpm | ставится сам | версия закреплена полем `packageManager` в `frontend/package.json` |
| Ключ Яндекс.Карт API v3 | — | без него карта не отрисуется |

## 1. Бэкенд

```bash
cd backend
YT_PROXY=localhost YT_TOKEN=dummy ./mvnw spring-boot:run -Dmaven.test.skip=true
```

Поднимается на `http://localhost:8080`.

Две неочевидные вещи в этой команде:

- **`YT_PROXY` и `YT_TOKEN` обязательны даже локально.** Их читает
  `QEnrichedRepository`, помеченный `@Repository` без ограничения по профилю,
  поэтому Spring резолвит плейсхолдеры на старте независимо от того, ходим мы
  в YTsaurus или нет. На профиле `mock` значения не используются — подойдут
  любые заглушки.
- **`-Dmaven.test.skip=true` — временный обход.** Тест
  `InMemoryRecentEventsCacheTest` отстал от текущей сигнатуры record
  `EnrichedEvent`, и без флага сборка падает на `testCompile`. Когда тест
  починят, флаг из этой инструкции нужно убрать.

Профиль по умолчанию — `mock` (`spring.profiles.default` в
`application.yaml`). В нём события в кэш кладёт `MockPoller`: раз в две
секунды одна правка в одном из десяти зашитых мест. Это не живой поток
Википедии, а данные для разработки UI.

Проверить, что бэкенд отвечает:

```bash
curl -s "http://localhost:8080/api/v1/hexagons/active?min_lng=37.31&min_lat=55.57&max_lng=37.85&max_lat=55.91&zoom=10"
```

Пустой список `hexagons` — нормальный ответ, а не ошибка: значит, в этом
прямоугольнике за окно кэша правок не было.

## 2. Фронтенд

```bash
cd frontend
pnpm install
cp .env.example .env    # и вписать ключи в VITE_YMAPS_API_KEY через запятую
pnpm dev
```

Открыть `http://localhost:5173/map`.

Dev server проксирует `/api` на `http://localhost:8080`, поэтому бэкенд должен
быть уже поднят. **`pnpm preview` прокси не настраивает** — прокси объявлен
только для `server` в `vite.config.ts`, — так что сквозную проверку
«браузер → `/api` → бэкенд» делаем на `pnpm dev`, а `preview` используем
только чтобы посмотреть на прод-сборку.

## 3. Проверки перед ревью

```bash
cd frontend
pnpm test
pnpm lint
pnpm build
```

Полный список команд фронтенда — в [frontend/README.md](../../frontend/README.md).

## Что сейчас не работает по-настоящему

Чтобы не принимать заглушку за готовую функциональность:

- **Живого потока правок нет.** `YtQueuePoller` — пустой класс, данные на
  локальном запуске всегда генерирует `MockPoller`. Пока это так, продуктовый
  MVP не считается готовым, и демо на этих данных нельзя называть живой картой.
- **Дашборд — честная заглушка** до появления контракта по исторической
  аналитике между B и F1.
- **Деплой не настроен и до появления живого бэкенда не делается.** Требование
  к будущему хостингу одно: `BrowserRouter` требует отдавать `index.html` на
  любой неизвестный путь, иначе прямое открытие `/map` вернёт 404.
