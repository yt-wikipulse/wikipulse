# Локальный запуск

Как поднять WikiPulse на своей машине с нуля. Шаги проверены на чистом клоне;
если шаг не работает — это баг документа, а не твоей машины.

Грабли, которые встречались в процессе, вынесены в
[troubleshooting.md](troubleshooting.md).

## Что нужно поставить

| Инструмент | Версия | Зачем |
|---|---|---|
| JDK | 17 | `java.version` в `backend/pom.xml`; проверено на 17.0.20 |
| Node.js | `^20.19` или `>=22.12` | требование Vite 8; проверено на 24.18 |
| pnpm | ставится сам | версия закреплена полем `packageManager` в `frontend/package.json` |
| Ключ Яндекс.Карт API v3 | — | без него карта не отрисуется |

## 1. Бэкенд

```bash
cd backend
SPRING_PROFILES_ACTIVE=mock YMAPS_API_KEY=<ключ> ./mvnw spring-boot:run
```

Поднимается на `http://localhost:8080`.

- **`SPRING_PROFILES_ACTIVE=mock` обязателен.** Профиль по умолчанию —
  `yt` (`spring.profiles.default` в `application.yaml`), а он ходит в кластер
  по RPC на порт 9013, который из домашних сетей обычно закрыт. Без кластера
  нужен `mock`.
- **`YT_PROXY` и `YT_TOKEN` на профиле `mock` не нужны.** Бины, которые их
  читают (`QEnrichedRepository`, `YtAggregatesRepository`), помечены
  `@Profile("yt")`, поэтому плейсхолдеры на `mock` не резолвятся вовсе.
- **`YMAPS_API_KEY` нужен, чтобы отрисовалась карта.** Где взять ключ и что с
  ним сделать — в [frontend/README.md](../../frontend/README.md). Без ключа
  бэкенд поднимется и данные отдаст, но карта покажет экран ошибки.

На профиле `mock` события в кэш кладёт `MockPoller`: раз в две секунды одна
правка в одном из десяти зашитых мест. Это не живой поток Википедии, а данные
для разработки UI. Дашборд на этом профиле обслуживает `MockDashboardService`
— форма ответа настоящая, числа выдуманные.

Проверить, что бэкенд отвечает:

```bash
curl -s "http://localhost:8080/api/v1/hexagons/active?min_lng=37.31&min_lat=55.57&max_lng=37.85&max_lat=55.91&zoom=10"
```

Пустой список `hexagons` — нормальный ответ, а не ошибка: значит, в этом
прямоугольнике за окно кэша правок не было.

## 2. Фронтенд

```bash
cd frontend
pnpm install
pnpm dev
```

Открыть `http://localhost:5173/map`.

Dev server проксирует `/api` на `http://localhost:8080`, поэтому бэкенд должен
быть уже поднят. **`pnpm preview` прокси не настраивает** — прокси объявлен
только для `server` в `vite.config.ts`, — так что сквозная проверка
«браузер → `/api` → бэкенд» возможна только на `pnpm dev`; `preview` показывает
прод-сборку и ничего больше.

## 3. Проверки перед ревью

```bash
cd frontend
pnpm test
pnpm lint
pnpm build
```

Бэкенд:

```bash
cd backend
SPRING_PROFILES_ACTIVE=mock ./mvnw test
```

Профиль здесь тоже обязателен: без него `WikiPulseProjectApplicationTests`
поднимает контекст на профиле `yt` и падает.

Полный список команд фронтенда — в [frontend/README.md](../../frontend/README.md).

## Чего не даёт локальный запуск

Живая карта и дашборд реализованы полностью, но на профиле `mock` данные
ненастоящие:

- **Живого потока правок нет.** `MockPoller` выдаёт правку раз в две секунды в
  одном из десяти зашитых мест. Настоящий поток читает `YtQueuePoller` из
  очереди `q_enriched`, а для этого нужен доступ к кластеру и профиль `yt`.
- **Дашборд считает не по витринам.** `MockDashboardService` отдаёт
  детерминированные фикстуры в форме контракта; настоящие числа приходят из
  витрин через `YtDashboardService`.
- **Демо на этих данных нельзя называть живой картой.** Форма ответов совпадает
  с продовой, содержание — нет.

Требование к хостингу одно: `BrowserRouter` требует отдавать `index.html` на
любой неизвестный путь, иначе прямое открытие `/map` вернёт 404.
