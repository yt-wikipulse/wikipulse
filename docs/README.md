# Документация

Разделы пронумерованы по порядку чтения: от «что делаем» через «как устроено»
к «как это эксплуатировать». Номер — часть имени папки, чтобы листинг сам собой
шёл в правильном порядке.

Если не знаешь, куда положить документ: описание границы между компонентами —
в `03-contracts`, причина принятого решения — в `04-decisions`, пошаговая
инструкция — в `05-runbooks`.

---

## 02-architecture — как система устроена

Внутреннее устройство компонентов: из чего состоят, как общаются, что кэшируют.
Границы между ними описаны не здесь, а в `03-contracts`.

- [overview.md](02-architecture/overview.md) — схема потоков данных целиком,
  список компонентов и их владельцев.
- [pipeline.md](02-architecture/pipeline.md) — producer, SPYT-джобы,
  что работает постоянно, что по расписанию, что будет при падении.
- [backend.md](02-architecture/backend.md) — устройство REST-сервиса,
  как события доезжают до фронта, конфигурация.
- [frontend.md](02-architecture/frontend.md) — карта и дашборд, работа с потоком
  событий, поведение при разрыве связи.
- [frontend-plan.md](02-architecture/frontend-plan.md) — этапы реализации
  frontend, foundation, разделение работы двух разработчиков и критерии приёмки.
- `diagrams/` — исходники картинок, если текстом диаграмму не выразить.

## 03-contracts — границы между компонентами

Самый важный раздел: пока контракты не зафиксированы, команда блокирует сама
себя. По ТЗ заполняется в первую неделю, до кода. Источник истины — если код
разошёлся с этими документами, это баг.

- [README.md](03-contracts/README.md) — порядок работы и правила изменения
  контрактов.
- [data-sources.md](03-contracts/data-sources.md) — поля, которые реально отдают
  поток правок Википедии и дампы координат.
- [yt-schemas.md](03-contracts/yt-schemas.md) — схемы таблиц и очередей YT.
  Общий контракт пайплайна и бэкенда.
- [rest-api.md](03-contracts/rest-api.md) — эндпоинты и форматы ответов.
  Общий контракт бэкенда и фронтенда.

## 04-decisions — почему сделали именно так

Журнал архитектурных решений (ADR): одно решение — один файл, после мержа
не редактируется. Нужен, чтобы через месяц не обсуждать заново отвергнутые
варианты и чтобы было что ответить на защите.

- [README.md](04-decisions/README.md) — когда заводить ADR и список принятых.
- [template.md](04-decisions/template.md) — шаблон: контекст, варианты,
  решение, последствия.

## 05-runbooks — как запустить и как чинить

Пошаговые инструкции. Проверяются на чистом клоне: если шаг работает только
потому, что у тебя уже что-то настроено, шаг описан неверно.

- [local-setup.md](05-runbooks/local-setup.md) — поднять проект локально с нуля.
- [troubleshooting.md](05-runbooks/troubleshooting.md) — копилка граблей.
  Потратил больше получаса на проблему — запиши сюда.
