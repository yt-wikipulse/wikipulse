# Контракт: внешние источники данных

Граница между проектом и чужими сервисами: что WikiPulse берёт снаружи,
какие поля из этого реально читает и на каких условиях это разрешено.

Источников четыре: поток правок Wikimedia и дамп Wikidata питают пайплайн,
MediaWiki Action API вызывается прямо из браузера, JavaScript API Яндекс Карт
рисует карту.

## Поток правок Wikimedia (EventStreams)

```
https://stream.wikimedia.org/v2/stream/recentchange
```

Server-Sent Events, публичный, без ключа и регистрации. Читает
[`bigdata/src/bigdata/jobs/ingestor.py`](../../bigdata/src/bigdata/jobs/ingestor.py),
пишет в `q_raw` пачками по 100 строк одним соединением, с заголовками
`User-Agent` и `Last-Event-ID`.

| Поле события | Куда едет | Зачем |
|---|---|---|
| `wiki` | `wiki` | языковой раздел, ключ джойна со справочником |
| `title` | `title` | заголовок статьи; подчёркивания заменяются пробелами |
| `title_url` | `url` | готовая ссылка на статью |
| `timestamp` | `event_ts` | время правки, unix-секунды |
| `revision.new` | часть `event_id` | номер новой ревизии |
| `notify_url` | `diff_url` | ссылка на диф правки |
| `length.new`, `length.old` | `length_update` | разность даёт прирост в байтах |
| `bot` | — | фильтр: правки ботов отбрасываются |
| `namespace` | — | фильтр: только `0`, то есть статьи |
| `type` | — | фильтр: только `edit` и `new` |

Остальное поток тоже присылает — `meta`, `user`, `comment`, `minor`,
`server_name` и прочее, — но ингестор это не читает и в `q_raw` не кладёт.
Схема очереди — в [yt-schemas.md](yt-schemas.md).

`event_id` собирается как `{wiki}|{revision.new}` — например
`enwiki|1372099064`. Номер ревизии уникален внутри своего раздела, но не
между разделами, поэтому раздел входит в ключ. Этот идентификатор служит
ключом дедупликации на всём пути: от очереди до кэша живой карты и до дедупа
в джобе витрин.

## Дамп Wikidata

```
https://dumps.wikimedia.org/wikidatawiki/entities/latest-all.json.gz
```

Полный дамп сущностей, по одному JSON-объекту на строку. Читает
[`bigdata/src/bigdata/scripts/load_dict_coords_full.py`](../../bigdata/src/bigdata/scripts/load_dict_coords_full.py)
одним потоковым соединением, с распаковкой на лету; пишет справочник
`dict/coords`.

| Путь в JSON | Куда едет |
|---|---|
| `claims.P625[0].mainsnak.datavalue.value.latitude` | `lat` |
| `claims.P625[0].mainsnak.datavalue.value.longitude` | `lon` |
| `sitelinks.<wiki>.title` | `title`, по строке на каждый языковой раздел |

`P625` — свойство «координаты объекта». Сущности без него пропускаются
дешёвой проверкой подстроки `"P625"` в сырой строке, до разбора JSON.

Из сайтлинков берутся только языковые разделы Википедии — имя оканчивается
на `wiki` и это не `wikidatawiki`, `commonswiki`, `metawiki`, `abstractwiki`.
Так фильтр справочника совпадает с фильтром ингестора: иначе в справочнике
лежали бы ключи, которые никогда не совпадут с событием.

Для пробного прогона у загрузчика есть `--max-rows`: проверять изменения
в парсере на полном дампе не нужно.

## MediaWiki Action API

```
https://<раздел>.wikipedia.org/w/api.php
```

Единственный источник, к которому ходит не пайплайн, а браузер
пользователя — [`frontend/src/api/wikiDiff.ts`](../../frontend/src/api/wikiDiff.ts).
Бэкенд диф не проксирует и не хранит.

| Запрос | Зачем |
|---|---|
| `action=compare&fromrev=&torev=&prop=diff` | HTML-таблица дифа двух ревизий |
| `action=query&prop=revisions&rvprop=ids&rvlimit=1` | номера ревизий, если их не удалось достать из `diff_url` |

Оба запроса идут с `format=json`, `formatversion=2` и `origin=*` — последнее
включает анонимный CORS, без него браузер не отдал бы ответ странице.
Домен берётся из `url` события, то есть у каждой правки спрашивается её
собственный языковой раздел. Из разобранного дифа показываются первые
8 строк.

## JavaScript API Яндекс Карт

```
https://api-maps.yandex.ru/v3/
```

Скрипт грузится из кода
([`loadYmaps.ts`](../../frontend/src/components/LiveMap/loadYmaps.ts)),
ключ приходит с бэкенда по `GET /api/v1/config` — см.
[rest-api.md](rest-api.md). Ключ публичный: он уходит в браузер и виден
в отладчике, а от чужого использования его защищает ограничение по
HTTP Referer в Кабинете разработчика.

## Юридические обязательства

Это не юридическая консультация, а список учтённого в коде и того, что
обязан сделать форкер.

### Тексты Википедии — CC BY-SA

Статьи Википедии распространяются по лицензии
[Creative Commons Attribution-ShareAlike](https://creativecommons.org/licenses/by-sa/4.0/)
(актуальная версия — 4.0, часть старых материалов доступна ещё и по GFDL):
при воспроизведении текста нужно указывать авторство, сохранять ссылку
на лицензию и распространять производное на тех же условиях.

Заголовки, ссылки и счётчики правок — фактические сведения, лицензией они
не покрыты; текст дифа в поповере — покрыт. Сейчас каждая правка ведёт
ссылкой на статью и на диф в самой Википедии и показывается только начало
дифа, но явной строки с указанием источника и лицензии рядом с текстом
в интерфейсе нет. **Форкер, поднимающий сервис публично, обязан её
добавить.**

### Данные Wikidata — CC0

Содержимое Wikidata выпущено под
[CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/): координаты
можно использовать без указания авторства.

### User-Agent policy Wikimedia

[Политика Wikimedia](https://meta.wikimedia.org/wiki/User-Agent_policy)
требует от автоматических клиентов информативный `User-Agent` с рабочим
способом связи; с пустым или обобщённым заголовком можно получить `403`,
а при нагрузке — бан по IP. Заголовок собирается один раз в
`runtime.USER_AGENT` и уходит и в SSE-поток, и в загрузку дампа:

```
WikiPulse/0.1 (<значение WIKIPULSE_CONTACT>)
```

`WIKIPULSE_CONTACT` — переменная окружения, по умолчанию канонический URL
проекта. **Форкер обязан подставить свой контакт**: URL своего репозитория
или адрес почты. Запросы фронтенда к Action API политика не затрагивает —
их делает браузер пользователя со своим `User-Agent`.

`dumps.wikimedia.org` — общий ресурс фонда: качать в одно соединение, без
параллельной качки кусками, и не чаще, чем выходит новый дамп, то есть раз
в неделю.

### Условия использования API Яндекс Карт

Ключ выдаётся в Кабинете разработчика, использование регулируется
[условиями использования API Яндекс Карт](https://yandex.ru/legal/maps_api/).
Практические следствия:

- **Копирайты, логотип и кнопка перехода в Яндекс Карты должны быть видны
  и не перекрыты.** Поэтому на узких экранах блок копирайтов переставляется,
  а не прячется.
- **Бесплатный тариф ограничен по числу загрузок карты в сутки.**
  Исчерпание квоты выглядит как «скрипт загрузился, а карта не рисуется» —
  симптом разобран в [troubleshooting.md](../runbooks/troubleshooting.md).
- **Ключ ограничивается по HTTP Referer** — единственная защита публичного
  ключа, и настроить её должен владелец стенда.

Свой ключ форкер получает сам, порядок — в
[frontend/README.md](../../frontend/README.md). Чужой ключ в репозитории —
это и нарушение условий, и чужой счёт.
