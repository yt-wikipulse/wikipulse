# Контракт: REST API

Граница между бэкендом и фронтендом. Два экрана: живая карта и дашборд.

## Общие правила

- Базовый путь `/api/v1`. Все эндпоинты — `GET`, тела запроса нет ни у одного.
- Формат JSON, имена полей — `snake_case`.
- Карту фронтенд опрашивает раз в 2,5 секунды, дашборд запрашивает при
  открытии экрана и при смене периода.

Записи ответов объявлены в коде в camelCase, а в `snake_case` их переводит
единственный ключ конфигурации `spring.jackson.property-naming-strategy:
SNAKE_CASE`. Изменить его — молча сломать фронтенд.

## Ошибки

Формат — Problem Details (RFC 9457), `Content-Type: application/problem+json`:

```json
{
  "type": "about:blank",
  "title": "Bad Request",
  "status": 400,
  "detail": "zoom must be between 0 and 30"
}
```

| Код | Когда | `detail` |
|---|---|---|
| `400` | не прошла проверка параметров эндпоинта | человекочитаемая причина |
| `400` | нет обязательного параметра или он не парсится | текст Spring про параметр |
| `404` | неизвестный путь | текст Spring |
| `405` | метод не поддерживается | текст Spring |
| `503` | не прочитались таблицы YT | `storage is temporarily unavailable` |
| `500` | всё остальное неожиданное | `internal error` |

Наружу из `5xx` уходит статичный текст без подробностей: пути таблиц, имя
кластера и сообщение YT остаются в логе. `503` возможен только на профиле `yt`.

## `GET /api/v1/hexagons/active`

Активность в видимой части карты. Фронтенд присылает прямоугольник экрана
и текущий зум, бэкенд сам выбирает резолюцию H3 и отдаёт готовые ячейки.

| Параметр | Тип | Обяз. | Описание |
|---|---|---|---|
| `min_lng` | number | да | западная граница экрана |
| `min_lat` | number | да | южная граница |
| `max_lng` | number | да | восточная граница |
| `max_lat` | number | да | северная граница |
| `zoom` | integer | да | зум карты, бэкенд переводит его в резолюцию H3 |

Значений по умолчанию нет ни у одного параметра: отсутствие любого — `400`.

```http
GET /api/v1/hexagons/active?min_lng=37.31&min_lat=55.57&max_lng=37.85&max_lat=55.91&zoom=10
```

```json
{
  "hexagons": [
    { "h3_index": "8611aa7afffffff", "events_count": 1, "events": [
      { "id": "ruwiki|142857001",
        "title": "Москва",
        "url": "https://ru.wikipedia.org/wiki/Москва",
        "length_update": 234,
        "diff_url": "https://ru.wikipedia.org/w/index.php?diff=142857001&oldid=142856900",
        "event_ts": 1788080804 }
    ] }
  ]
}
```

Резолюция в ответе не указана: фронтенд знает её по своему зуму. Лестница
«зум → резолюция» задаётся ключами `app.live.zoom-r*-max` — см.
[configuration.md](../runbooks/configuration.md).

### Поля события

| Поле | Что означает |
|---|---|
| `id` | `event_id` из очереди: вики и номер ревизии |
| `title` | заголовок статьи |
| `url` | ссылка на статью |
| `length_update` | прирост длины статьи в байтах, бывает отрицательным |
| `diff_url` | ссылка на диф правки; фронтенд достаёт из неё номера ревизий |
| `event_ts` | время правки, unix-секунды |

`events_count` — **полное** число событий ячейки за окно, а массив `events`
обрезан до 50 самых свежих (`app.live.hexagon-events-cap`) и отсортирован по
`event_ts`, новые первыми. Счётчик и длина массива расходятся штатно, это не
рассинхрон.

### Проверка параметров

| Условие | Ответ |
|---|---|
| `min_lng >= max_lng` или `min_lat >= max_lat` | `400`, `min_lng/min_lat must be less than max_lng/max_lat` |
| `zoom` вне `app.live.zoom-min`…`zoom-max` | `400`, `zoom must be between 0 and 30` |

В текст ошибки подставляются настроенные границы `app.live.zoom-min`
и `zoom-max`, поэтому со значениями по умолчанию он выглядит так, как
в таблице выше. Прямоугольник, пересекающий 180-й меридиан, не
поддерживается: у него `min_lng > max_lng`, и запрос отбивается как
невалидный.

### Окно

События живут в кэше бэкенда **30 минут** (`app.live.window-minutes`). Ячейки
без событий за это окно в ответ не попадают: пустой список `hexagons` —
нормальный ответ, а не ошибка. Гарантии кэша — в
[backend.md](../architecture/backend.md).

## `GET /api/v1/dashboard`

Историческая аналитика поверх витрин YT.

| Параметр | Тип | Обяз. | Описание |
|---|---|---|---|
| `period` | `24h` \| `7d` \| `30d` | да | окно агрегации |
| `limit` | integer, 1–100 | нет | длина топов, по умолчанию 10 |

Оба значения проверяет контроллер, до обращения к сервису и кэшу.

```http
GET /api/v1/dashboard?period=24h
```

```json
{
  "period": "24h",
  "generated_at": 1788080783,
  "bucket_seconds": 3600,
  "total_edits": 25728,
  "trends": [{ "bucket_ts": 1787994000, "edits_count": 1071 }],
  "top_articles": [
    { "title": "Federal Reserve",
      "url": "https://en.wikipedia.org/wiki/Federal_Reserve",
      "edits_count": 18420 }
  ],
  "top_geo": [
    { "h3_parent": "862664c1fffffff",
      "top_title": "Teotihuacán",
      "top_url": "https://en.wikipedia.org/wiki/Teotihuacan",
      "edits_count": 9840,
      "articles_count": 312 }
  ]
}
```

### Поля

| Поле | Что означает |
|---|---|
| `period` | эхо запроса |
| `generated_at` | время сборки ответа, unix-секунды; не время пересчёта витрин |
| `bucket_seconds` | шаг между точками `trends` |
| `total_edits` | сумма `edits_count` по точкам `trends` из этого же ответа |
| `trends[].bucket_ts` | начало интервала, unix-секунды |
| `top_articles[]` | самые правимые статьи периода |
| `top_geo[].h3_parent` | H3-ячейка резолюции 6 |
| `top_geo[].top_title` | самая правимая статья внутри ячейки |
| `top_geo[].articles_count` | сколько разных статей затронуто в ячейке |

Время везде в unix-секундах, как `event_ts` в очереди; ISO-строк нет.

### Периоды и витрины

Наружу отдаются `24h`, `7d`, `30d`; топы хранят период строкой в часах,
поэтому бэкенд переводит значение перед запросом:

| Запрос | В витрине |
|---|---|
| `24h` | `24h` |
| `7d` | `168h` |
| `30d` | `720h` |

Перевод касается только `top_articles` и `top_geo`: у `marts/trends` колонки
периода нет, точки выбираются условием `bucket_ts >= now - длительность
периода`. Схемы — в [yt-schemas.md](yt-schemas.md).

### Шаг графика

| `period` | `bucket_seconds` | Точек в графике |
|---|---|---|
| `24h` | 3600 (час) | до 24 |
| `7d` | 3600 (час) | до 168 |
| `30d` | 86400 (сутки) | до 30 |

Витрина хранит только часовые строки, поэтому суточные точки для `30d`
бэкенд складывает сам, уже после чтения.

Витрина может быть ещё не посчитана — тогда `trends`, `top_articles`
и `top_geo` приходят пустыми массивами, а `total_edits` равен нулю.
Это нормальный ответ, не ошибка.

### Ошибки

| Условие | Ответ |
|---|---|
| `period` вне `24h`, `7d`, `30d` | `400`, `period must be one of 24h, 7d, 30d` |
| `limit` вне `1…100` | `400`, `limit must be between 1 and 100` |
| нет `period` или `limit` не число | `400` от Spring |
| витрины недоступны | `503` |

Устаревшие данные вместо ошибки не отдаются: ответ либо свежий, либо `503`.
Что кэшируется и на сколько — в [backend.md](../architecture/backend.md).

### Согласованность

Три блока читаются из трёх разных витрин отдельными запросами, между которыми
батч-джоба может пересчитать часть таблиц, — блоки способны относиться
к соседним пересчётам. `total_edits` при этом считается **из тех же точек
`trends`**, что уехали в ответ, поэтому сумма на экране всегда сходится
с графиком.

### Профиль mock

Эндпоинт отвечает и без кластера: на профиле `mock` его обслуживает
`MockDashboardService`, читающий фикстуры из
`backend/src/main/resources/fixtures/`. Форма ответа та же, `limit` режет
топы так же, `503` не бывает, а `generated_at` берётся из фикстуры и потому
не двигается от запроса к запросу.

## `GET /api/v1/config`

Настройки, которые фронтенд получает в рантайме. Параметров нет.

```json
{
  "ymaps_api_key": "<ключ из Кабинета разработчика>"
}
```

Ключ приходит из окружения бэкенда (`app.ymaps.api-key`, переменная
`YMAPS_API_KEY`), а не из сборки фронтенда: смена ключа не требует пересборки
образа `web`, а форкер подставляет свой ключ, не трогая код. Как получить
ключ — в [frontend/README.md](../../frontend/README.md), условия
использования — в [data-sources.md](data-sources.md).

Если ключ не задан, отдаётся `200` с `"ymaps_api_key": ""`. Отсутствие ключа
не ошибка запроса, поэтому не `5xx`: карта не инициализируется и показывает
ошибку загрузки, остальная страница работает.

## Дифа правки в API нет

Текст изменений фронтенд запрашивает у MediaWiki Action API прямо из
браузера, минуя бэкенд, — см. [data-sources.md](data-sources.md).
