# WikiPulse frontend

React SPA с живой картой правок Википедии и дашбордом исторической аналитики.

## Что нужно поставить

| Инструмент | Версия | Почему так |
|---|---|---|
| Node.js | `^20.19` или `>=22.12` | требование Vite 8, продублировано в `engines` и `.nvmrc` |
| pnpm | ставится сам | версия закреплена полем `packageManager` |
| Ключ Яндекс.Карт | — | без него карта не отрисуется, см. ниже |

`nvm use` подхватит версию из `.nvmrc` — там `22`, как в продовом образе
сборки (`deploy/web.Dockerfile`).

## Ключ Яндекс.Карт

Это единственная внешняя зависимость, которую нельзя обойти: JavaScript API
Яндекс Карт не работает без ключа.

1. **Получить ключ.** В Кабинете разработчика Яндекса нужен ключ для
   **JavaScript API и HTTP Геокодер**. Проект грузит `api-maps.yandex.ru/v3/`,
   ключи от других API Яндекса не подойдут.

2. **Прописать Referer.** В настройках ключа обязательно указать адрес сайта в
   ограничении по HTTP Referer. Без этого карта не отрисуется даже с валидным
   ключом, а ошибка придёт изнутри API и будет невнятной. Голый IP там не
   принимается — нужен домен; для локальной разработки подходит `localhost`.

3. **Отдать ключ бэкенду.** Фронтенд ключ не собирает и не хранит: он получает
   его в рантайме из `GET /api/v1/config`. Бэкенд читает ключ из переменной
   окружения `YMAPS_API_KEY`:

   ```bash
   cd backend
   YMAPS_API_KEY=<ключ> YT_PROXY=localhost YT_TOKEN=dummy \
     SPRING_PROFILES_ACTIVE=mock ./mvnw spring-boot:run
   ```

Ключ публичный: он уходит в браузер и виден в отладчике. Защищает его только
ограничение по Referer — секретом он не является.

**У бесплатного ключа лимит 100 загрузок карты в сутки.**

Если ключ не задан, `GET /api/v1/config` вернёт пустую строку — это не ошибка.
Карта покажет экран «Не удалось загрузить карту» с кнопкой повтора, остальная
страница продолжит работать.

## Локальный запуск

```bash
pnpm install
pnpm dev
```

Открыть `http://localhost:5173/map`.

Dev server проксирует `/api` на `http://localhost:8080`, **поэтому бэкенд
должен быть запущен** — иначе не будет ни данных, ни ключа Карт. Другой адрес
бэкенда задаётся переменной `BACKEND_URL`.

`pnpm preview` прокси не настраивает: он объявлен только для `server` в
`vite.config.ts`. Сквозная проверка «браузер → `/api` → бэкенд» возможна
только на `pnpm dev`; `preview` показывает прод-сборку и ничего больше.

Моковых данных на фронтенде нет: карта показывает то, что ответил бэкенд.
Данные для разработки даёт сам бэкенд на профиле `mock`.

## Маршруты

- `/map` — живая карта;
- `/dashboard` — дашборд исторической аналитики;
- `/` — redirect на `/map`;
- неизвестный URL — страница «Не найдено».

Хостинг должен отдавать `index.html` на любой неизвестный путь: иначе прямое
открытие `/map` вернёт 404, потому что роутинг клиентский (`BrowserRouter`).

|---|---|

| `pnpm build` | TypeScript build и production bundle |
| `pnpm lint` | ESLint |
| `pnpm preview` | локальный preview production bundle |
| `pnpm test` | Vitest, один прогон |
| `pnpm test:watch` | Vitest в watch-режиме |
