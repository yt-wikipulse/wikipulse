# Роли и зоны ответственности

Роль — не должность, а ответ на два вопроса: у кого спрашивать и кто аппрувит
PR в этой части. Совмещать роли можно, оставлять зону без владельца — нет.

Команда: 5 человек. Состав треков менялся под скоуп MVP v1 — пайплайн почти
готов, дашборд отложен до v2, поэтому основная нагрузка ушла на бэкенд.

---

## Треки

Границы проведены по стыкам, а не по технологиям: каждый стык — это контракт,
у которого ровно две стороны.

| Трек | Зона | Владельцы |

| **P. Пайплайн** | SSE-сборщик, справочник координат, джоба обогащения | |
| **B. Бэкенд** | чтение `q_enriched`, кэш, H3, API — два человека | |
| **F1. Карта** | отрисовка гексагонов, поллинг, bbox и зум | |
| **F2. Свободный** | в MVP v1 у трека нет своей зоны, см. ниже | |

Внутри бэкенда есть естественный стык — `RecentEventsCache`: одна половина
наполняет его из очереди, вторая читает и отдаёт наружу. Удобная линия, чтобы
делить задачи между двумя людьми, но не повод заводить два трека.

## Ревью

Ревьюера выбирает автор PR. Правило одно: **не сам себе**, и по возможности
человек из другого трека — так к защите каждый понимает соседний кусок.

Очереди и схемы назначения нет: команда маленькая, все на виду, и написать
человеку напрямую дешевле, чем сверяться со списком.

## Разногласия

Спор — нормальная часть работы. Ссора начинается там, где спор не заканчивается
решением. Порядок эскалации:

1. **Внутри трека** — решает владелец трека.
2. **На стыке двух треков** — решают оба владельца: это их общий контракт.
3. **Не сошлись за рабочий день** — решает тимлид, без нового круга обсуждения.

Четыре правила, которые снимают большую часть споров:

- **Спор о фактах решается проверкой.** «Так быстрее», «так не выдержит поток» —
  это замер или спайк на полдня, а не аргументы в чате.
- **Таймбокс.** Спор дольше получаса уходит на уровень выше. Неидеальное решение
  сегодня дешевле идеального через три дня.
- **Решили — делаем.** Можно остаться при своём мнении и всё равно делать.
  Возражение фиксируем в [ADR](../docs/04-decisions/), чтобы вернуться к нему
  с данными, а не с эмоциями.
- **Вкусовщина не обсуждается.** Форматирование и стиль закрывает линтер.
  Правило, которое нельзя проверить автоматически, — это мнение, а не правило.

Отдельно: спор идёт про решение, а не про человека. Переход на личности
останавливает обсуждение сразу, независимо от того, кто прав по существу.

## Обязанности поверх треков

Это не отдельные люди, а нагрузка на кого-то из тех же пятерых.

**Тимлид** — интеграция, разблокировка, подготовка защиты.

**Дежурный по интеграции** — зелёный `main`, мержи, сквозной прогон. Ротация
по треку, неделя на человека: за 4,5 недели проекта круг проходит один раз.

| Неделя | Дежурный |
|---|---|
| 1 | |
| 2 | |
| 3 | |
| 4 | |

**Ответственный за README и сценарий защиты** — назначается на первой неделе,
не на последней. Иначе это делает тимлид ночью перед демо.

## Общая ответственность

Независимо от трека:

- контракты читают и поддерживают все, кого они касаются;
- увидел, что чужой трек блокирует твой, — говоришь сразу, а не за день
  до конца спринта;
- владелец документа отвечает за то, что документ не врёт (см.
  [правила ведения](documentation.md)).
