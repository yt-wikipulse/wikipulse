# Цикл работы с задачами

Задачи ведём в трекере SourceCraft. Статус задачи виден в нём же, дублировать
его в переписке не нужно — о событиях приходят уведомления.
Критерии готовности — в [workflow.md](workflow.md).

## Порядок

1. Создать задачу по форме или взять существующую.
2. Взять в работу: выставить себя ответственным.
3. Ветка `<тип>/<номер>-<суть>`, запушить её.
4. Делать задачу, коммитить в ветку.
5. Пройти самопроверку (ниже).
6. Открыть PR: заголовок — имя ветки, в описании первой строкой
   `#<номер задачи>` и строка «Как проверить». Сразу связать задачу с PR
   через меню связей.
7. Позвать рецензента.
8. После аппрува смержить squash-ом и удалить ветку.
9. Закрыть задачу руками — автозакрытия нет, в комментарий форму отчёта.

Задачу может создать любой. Типы веток — в [contributing.md](contributing.md).

## Форма задачи

```
Зачем: что это даёт проекту
Готово, когда: 1-2 строки, проверяемо
Зависит от: задача, человек или «ни от кого»
```

«Готово, когда» — критерий приёмки: сделано или нет. «Как проверить»
в PR и отчёте — шаг, которым результат воспроизводит другой человек.

Поля трекера: метка — трек, связи — блокирующие задачи,
ответственный — пусто, пока не взяли.

## Самопроверка перед ревью

- «Готово, когда» выполнено дословно;
- прогнано на чистом клоне;
- ветка обновлена от `main`;
- работа без кода лежит в `docs/` отдельным PR;
- [контракты](../docs/03-contracts/) обновлены, если PR их менял;
- документация — по [требованиям](documentation.md): решение и причина записаны;
- нет секретов, `.env`, локальных путей, отладочных выводов.

Не выполнено — ревьюера не зовём. Это единственный список перед ревью,
в `contributing.md` своего нет.

## Что смотрит ревьюер

- выполнено ли «Готово, когда»;
- воспроизводится ли результат по строке «Как проверить» из описания PR;
- не разошлись ли контракты с кодом;
- поймёт ли тот, кто в задаче не участвовал.

Ревьюер не переписывает решение: принимает или пишет, чего не хватает.
Спор о том, как правильнее, — в [ADR](../docs/04-decisions/).

## Форма отчёта

Комментарий при закрытии задачи:

```
Что сделано:
PR:
Как проверить:
Что изменилось в docs/:
Кого разблокировало:
```

«Что изменилось в docs/» заполняем по [требованиям](documentation.md).
«Как проверить» обязательна: без неё работа не закончена.
«PR» пустым не бывает — у задачи без кода это PR в `docs/`.
